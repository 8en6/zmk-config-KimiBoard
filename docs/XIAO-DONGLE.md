# KimiBoard Lite + XIAO nRF52840 USB受信機

## 状態

ビルド結果はこのブランチの最新GitHub Actions実行とPR #1を参照してください。
ビルド成功は実機動作の保証ではありません。

## 構成

KimiBoard Lite（子機）→ BLE → 追加のXIAO nRF52840（親機）→ USB → PC。

指定リポジトリの seeeduino_xiao_ble / PMW3610 配線をそのまま使用します。
親機へのセンサー・スイッチの配線追加は不要です。
PC側とのBluetoothペアリングは不要ですが、親子間はBLEです。
本体・親機の両方を書き換える必要があります。子機は単独でPCに接続できなくなります。
会社がUSB入力機器を制限している場合の利用可否は別途確認してください。

## ビルドの開始

1. リポジトリのActions画面を開きます。
2. フォークのActions有効化ボタンが表示される場合は有効にします。
3. buildワークフローのRun workflowでブランチ `codex/xiao-usb-dongle` を選びます。
   mainを選ぶと今回の構成は含まれません。
4. 全ビルド成功後、実行ページのArtifactsから `firmware` をダウンロードして展開します。
   新規ブランチのワークフローが表示されない場合は、有効化後にブランチへの追加コミットで開始できます。

## 使用するUF2

| ファイル | 書き込み先 |
|---|---|
| kimiboard-dongle-xiao.uf2 | 追加のXIAO。通常のUSB HID版（推奨） |
| kimiboard-dongle-xiao-studio.uf2 | 同じ追加XIAO。USB Studio編集機能付きの代替版 |
| kimiboard-lite-peripheral.uf2 | KimiBoard Lite本体 |
| settings_reset-seeeduino_xiao_ble-zmk.uf2 | 初回に両方のXIAOで使う初期化用 |
| kimiboard rgbled_adapter-seeeduino_xiao_ble-zmk.uf2 | 元の単体構成へ戻すためのファームウェア |

親機用の2種類はどちらか一方を使用します。
通常USB版にはStudio用CDCシリアルインターフェースを追加していません。
Studioを使う場合はStudio版を継続使用するのが簡単です。
通常USB版への切り替え時にStudio編集値が維持されることは検証していません。

## 今回の設定更新（接続済みの機器）

親機・子機の両方に最新の通常UF2を上書きしてください。接続済みならsettings_resetは通常不要です。
ZMK Studioで以前のキーマップが保存されている場合、ファームウェアの既定配列より保存値が優先されます。
親機を書き換えた後、https://zmk.studio/ にUSB接続して「Restore Stock Settings」を実行し、
今回の2レイヤー配列を読み込んで保存してください。以前のStudio編集内容は置き換わります。
初回の全設定消去と異なり、この操作はキーマップの復元です。

このファームウェアのStudio対応は標準ZMK Studioです。Sirocom Studioの独自設定には対応しません。
CPI・回転・AML・コンボの変更はソースを更新して再ビルドします。

## 初回書き込み

現在のStudio編集内容・ペアリング情報はresetで消えます。
必要な配列は先に記録してください。今回の配列はGitHub内の初期配列が基準です。

1. KimiBoard Lite本体をUSBで接続し、基板のリセットスイッチを素早く2回押してUF2ドライブを出します。
   キー配列中の「0キー」と基板のリセット操作を混同しないでください。
2. 初期化用UF2をコピーし、再起動後に数秒待ちます。
3. もう一度ブートローダーに入り、本体用 `kimiboard-lite-peripheral.uf2` をコピーします。
4. 追加XIAOも同様に初期化用UF2を適用してから、親機用UF2を書き込みます。
   リセットボタンがない基板では、メーカー指定のRST–GNDによるブートローダー操作を使います。
5. 両方を一度再起動し、近くに置きます。親機をデータ通信可能なUSBケーブルでPCへ接続し、
   本体の電源を入れます。親子は自動でペアリングします。
6. 初回は他の未ペアリングZMK子機を近くで起動しないでください。

初期化用UF2だけでは動作しません。必ずそれぞれの通常UF2を続けて書き込みます。

## 配列と機能

- CPI: 2000（子機側センサー設定）。
- 本体回転: 元の通常方向から180°固定。元からあるセンサーの取付方向補正とは別に、X/Yを両方反転。
- AML: 無効。DefaultとScrollの2レイヤーのみ。
- SW1: 200 ms未満の短押しで親機のBTホストプロファイルを1→2→3→1と切り替え。長押しは何もしません。
- SW2: 左クリック。SW3: 右クリック。SW4: 左クリック。
- SW2+SW3: 50 ms以内の同時押しで、両方を押している間のみスクロール。どちらかを離すと終了。
  コンボ成立時は左右クリックを出しません。
- その他の既存コンボ、文字入力、AMLレイヤー、マウス切替レイヤーは削除。
- USB接続中の出力はUSBのまま。SW1は子機の接続先や親子ペアリングを変更しません。
- スクロール倍率は既存の1/20を維持。CPIが400から2000に増えるため、同じボール移動でも
  スクロール量は従来より増えます。必要なら別途スクロール倍率を調整できます。
- SW番号は物理スイッチに対応し、本体を回転させても入れ替えません。
- 子機のRGBステータス表示は無効です。

## 実機チェック

1. SW2/SW4で左クリック、SW3で右クリックでき、ボール操作後も変化しないことを確認。
2. SW2+SW3を押している間だけスクロールし、片方を離すとポインター移動に戻ることを確認。
3. 180°回した本体で、ポインター上下左右が意図どおりか確認。
4. SW1の短押しのみでBTプロファイルが切り替わり、長押しでは変化しないことを確認。
5. USB抜き差しと本体電源の再投入後に再接続することを確認。

## 実装

単体用ビルドを維持し、dongle/peripheral shieldを追加。
PMW3610ドライバーを元のリビジョンで同梱し、子機ビルドのキーマップ参照だけをガードしました。
親機・子機でキー位置の変換と物理レイアウトを一致させています。
ZMK v0.3を維持し、west.yml内のrevision重複を除去しました。
